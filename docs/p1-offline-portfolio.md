# P1-03: сквозной service/portfolio fixture

Дополнение: теперь есть отдельный сценарий исходного LevelBreakoutStrategy без подмены сигнала. Он проходит от свечей/рынка до сделки и footer; ниже описан предыдущий controlled-signal этап. [Текущий приоритет и E01](e01-breakout-obstacle.md).

Полный набор: **746 passed** за 101.94 секунды в чистом окружении; пять новых тестов. `git diff --check` проходит.

Добавлена интеграционная проверка от cold restore до закрытия сервиса с одной реально открываемой paper-позицией. Позиция не вставляется в broker state и не переносится из checkpoint: общий evaluate создаёт decision, арбитр проверяет его, строит план и открывает позицию через PaperBroker.

Последовательность: service start → clock/scanner/bootstrap → transport/snapshots/trade → операторский Start → evaluate/arbiter → открытие → выход → shutdown/drain/footer. Market readiness и Start выполняются исходным кодом, без подмены start_block_reason.

## Что проверено

- Закрытие открытой позиции при shutdown.
- Закрытие по stop после снижения исполнимой цены стакана и прихода trade.
- Точное совпадение output events, closed_trades и итогового balance; отсутствие оставшихся positions/pending entries.
- Положительные комиссии и равенство итогового баланса начальному балансу плюс net PnL с числовым допуском pytest.approx только для этого арифметического тождества. Live/replay balance сравнивается точно.
- Незаметная подмена комиссии, net PnL на 0.01 или причины выхода в ожидаемых outputs приводит к отказу replay.
- Полный структурный журнал от header до footer проходит validator; offline не использует сеть, asyncio Tasks/gather/sleep.

Сравнение outputs сохраняет только ранее объявленные исключения run_summary.latencyMetrics/recorderHealth. Финансовые поля из сравнения не исключаются.

## Граница доказательства

Обе стороны используют одинаковый явно заданный тестовый signal provider вместо evaluate production-стратегии trend_structure. Торговые фильтры/арбитр, расчёт риска, paper execution и закрытие остаются исходными. Тестовая конфигурация содержит упрощённые экономические пороги; рабочие профили не менялись.

Это проверка исполнения и учёта сделки при контролируемом сигнале. Она не доказывает совпадение сигналов production-стратегий, прибыльность, partial fills, maker entry, add-ons, несколько позиций или полную replay parity реальной сессии. Runtime-подмена стратегии явно является частью fixture; проверка source fingerprint сама по себе не удостоверяет отсутствие таких подмен. parityReady остаётся false.

Новых дефектов в проверенных путях исполнения не выявлено; production-код в этом инкременте не менялся. Добавлено пять тестов. Следующий шаг — сценарий с исходной production-стратегией и рыночными входами, затем оставшиеся пути отказа и streaming/capture load validation перед новой записью.

Сервер не перезапускался. Новый длительный прогон пока не нужен.
