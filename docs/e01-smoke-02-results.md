# E01 smoke-02: вычислительная перегрузка и оптимизация

Источник: `data/e01-smoke-02`, 25 сентября 2026. Статус **invalid**. Первичные файлы сохранены; потоковый разбор — `analysis.json` в том же каталоге.

## Завершение и качество записи

- После Start прошло **970.73 секунды (16 минут 11 секунд)**. Штатного Stop/footer/result.json нет.
- Точная причина: `market processor lag exceeded 0.500s (lag=0.523s, queue=202)`, fast-поток ETHUSDT. Это превышение задержки обработки, а не заполнение очереди до предела 512.
- Проверены sequence и все хеши **601 255** сохранённых входов с привязкой к header. Последний hash: `5232c290fce56be4da199cdcc18d98d1c62125b15ab5f75b4f46dc06181552c1`. Целостность префикса не заменяет завершение или полный replay.
- Входной поток — 697.99 МБ; выходные события обоих портфелей — 852.45 МБ. Повторные снимки стали меньше, но backpressure сохранился.
- Clock: принято 55 из 170 замеров, 115 отклонены по RTT >400 мс; медиана 454.82 мс. Просрочка синхронизации отмечена в 111 из 3312 health-снимков (3.35%, не точная доля времени). В первом smoke было 693 из 5174 (13.39%). Более частый polling уменьшил наблюдаемые паузы, но качество RTT остаётся проблемой.

## Измеренное узкое место

По performance.json применение 594333 рыночных входов к двум движкам заняло суммарно **685.82 секунды**, максимум одного применения — 105.44 мс. Feed hashing/write — 22.78 секунды для этих входов. Суммарное время record() всех событий обоих портфелей — около 13.4 секунды; оно входит во время обработки, складывать их как независимые затраты нельзя. Вызов record() не включает предварительное построение payload.

Профилирование первых 20000 входов: compute_trade_flow — 15.47 секунды из 48.05 профилированных секунд; deepcopy — 9.72 секунды. Эти числа включают накладные расходы профилировщика. Внутри одной оценки рынка движок и несколько стратегий повторно рассчитывали одинаковые окна ленты; lower()/notional вызывались миллионы раз.

## Изменения

- Окна 5/15/60 секунд и предыдущий интервал формируются одним проходом. Сохраняются порядок элементов, границы окон, обработка неизвестной стороны и будущих событий, а также встроенный sum для прежнего результата floating-point.
- Движок передаёт каждой стратегии отдельную копию уже рассчитанного trade_flow на текущий observed_at_ms. Данные между оценками не кешируются. Отдельные вызовы стратегий без precomputed flow по-прежнему вычисляют его самостоятельно.
- Копирование JSON-структур E01 пропускает служебную работу deepcopy для неизменяемых скаляров. Изоляция изменяемых контейнеров портфелей, внутренние aliases/cycles и fallback для прочих типов сохранены.
- Торговые фильтры, частота оценки стратегий, universe, исполнение, лимиты RTT и queue lag не менялись. Профиль имеет метку v3; остальные настройки после smoke-01 сохранены.

Снижение времени — **23.8%**. Все выходные события совпали после исключения только случайного manifestId. Input hash одинаковый. На этом коротком фрагменте не было сделок; отдельно проверяется реальная breakout-стратегия со сделкой и переданным flow. 26 golden cases сохраняют результаты прежнего compute_trade_flow, включая несортированную ленту, границы окон, разные стороны, масштабы сумм и now_ms=None.

Это локальный замер на одном фрагменте, а не гарантия отсутствия задержек под живыми рыночными всплесками. Успех нового live smoke пока не подтверждён.

## Торговые наблюдения

Оба портфеля закрыли одинаковые три rejection-сделки: XPL +3.9276, NEAR −3.5780, XPL −3.5239 USDT. Баланс обоих в последнем снимке — 996.8258 USDT; у baseline осталась одна открытая позиция, у candidate — ни одной. Сравнивать конечную доходность этих портфелей без общей границы закрытия нельзя. Этот smoke не подтверждает и не опровергает торговую гипотезу E01.
