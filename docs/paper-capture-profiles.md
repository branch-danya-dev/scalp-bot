# Один бот: полная запись на 1, 12 или 24 часа

**Следующий назначенный запуск — [24-часовой экзамен текущего состава](paper-exam-24h.md)**.
Прежний план 1h → 12h заменён решением владельца. Старые профили доступны
для отдельных проверок; ниже сохранены их команды, а не обязательный порядок.

Все профили используют обычный тёмный UI с графиками, объёмами и разбором
сделок: **http://127.0.0.1:8000/**. Один engine и один paper-портфель.
Рыночные данные поступают с Bybit; реальные ордера не отправляются.

| Параметр | Часовой профиль | Профиль на 12 часов | Суточный экзамен |
|---|---|---|---|
| Файл | `.env.paper-capture-1h` | `.env.paper-capture-12h` | `.env.paper-capture-24h` |
| Пробой уровня | Включён | Включён | Включён |
| Отбой от уровня | Включён | Включён | Включён |
| Трендовый откат | Выключен | Включён | Выключен |
| Гипотеза цены · BETA | Выключена | Включена записанной командой до старта | Выключена |
| Ликвидность стакана | Подтверждение | Подтверждение | Подтверждение |
| Торговля после Start | 3600 секунд | 43200 секунд | 86400 секунд |
| Свободное место перед запуском | Не менее 20 GiB | Не менее 100 GiB | Не менее 200 GiB |

Ликвидность стакана самостоятельно не открывает позиции. Поэтому все пять
переключателей означают четыре стратегии входа и один источник подтверждений.
Состав зафиксирован на время записи: переключатели в UI заблокированы.
Обычный запуск без этих профилей сохраняет возможность переключения.

## Запуск

Из корня проекта, в PowerShell:

```powershell
.\scripts\run-paper-capture-1h.ps1
```

Дождаться завершения предварительных тестов и проверки связи с Bybit.
Открыть UI, дождаться готовности рыночных данных и нажать **Start**.
Час отсчитывается от Start; штатные условия прогрева и допуска сохраняются.
По окончании бот закроет оставшиеся paper-позиции и запишет результат.
После остановки торговли запись **завершается автоматически**. Дождаться в UI
сообщения **«Запись сохранена»** (`capture.status=sealed`), затем проверить
запись в другом терминале. Графики и сделки остаются доступны как снимок на
конец прогона; новые рыночные события больше не записываются. Ctrl+C нужен
только для закрытия сервера, когда просмотр закончен:

```powershell
.\scripts\check-paper-capture.ps1 -Profile 1h
```

Команда выводит выбранную папку и проверяет последнюю запись соответствующего
профиля. Успех — `Replay matched` и `status: baseline_replay_matched` в
`capture-check.json`. Для конкретной папки:

```powershell
.\scripts\check-paper-capture.ps1 -Directory "G:\scalp-bot\data\paper-captures\<имя-папки>"
```

Для отдельной записи всех стратегий на 12 часов:

```powershell
.\scripts\run-paper-capture-12h.ps1
```

Порядок тот же: Start в UI → автостоп → «Запись сохранена» → проверка:

```powershell
.\scripts\check-paper-capture.ps1 -Profile 12h
```

Проверка воспроизводимости не оценивает качество стратегии. Перед длинным
запуском у часового результата также проверить `summary.reason=duration_elapsed`,
`summary.elapsedSeconds >= 3600`, рыночные разрывы, задержки и реальные сделки.
Ручной Stop также автоматически завершает запись и сохраняет возможность проверить неполный по длительности период,
но не считается завершённым часовым испытанием. При ошибке проверки сохранить
папку целиком; не начинать 12 часов, пока причина не разобрана.

Для проверки только конфигурации и свободного места, без сервера и Bybit:

```powershell
.\scripts\run-paper-capture-1h.ps1 -Check
.\scripts\run-paper-capture-12h.ps1 -Check
.\scripts\run-paper-capture-24h.ps1 -Check
```

## Что фиксируют профили

Основа — checked-in `.env.example`, затем соответствующий профиль. Локальный
`.env` и оставшиеся `SCALP_*` предыдущих запусков не используются. После выхода
окружение терминала восстанавливается. Комиссии берутся из настроек профиля
(`configured`), запрос учётных данных биржи не нужен. E01/E06 и исследовательская
promotion policy отключены. Исправление конфликта `1h_only` входит в текущий код.
Торговые правила, общий риск, арбитраж и ограничения числа позиций сохранены.

Каждый запуск получает **новую папку**
`data/paper-captures/1h-<дата>-<id>`, `12h-<дата>-<id>` или `24h-<дата>-<id>`:

- `session-*.jsonl` — решения, сделки, графики и итог портфеля;
- `session-*.inputs.jsonl.gz` — полные входы engine: стаканы, лента, свечи,
  REST-контекст, сканер, наблюдения времени, планирование, переподключения и
  команды UI;
- `capture-manifest.json` — фактические настройки, версии и хеши кода;
- `source-at-capture.zip` — исходники Python и описание зависимостей,
  соответствующие manifest; секреты и локальный `.env` не включаются;
- `capture.json` — состояние записи и потери; `terminal.log` — журнал запуска;
- `capture-check.json` — результат последующей проверки.

Прежние папки не перезаписываются и не требуют удаления. Во время записи не
менять код и не обновлять зависимости. После изменения исходников старый журнал
проверяется с сохранённым кодом через `replay-paper-capture.py --source-root`
и с прежними версиями зависимостей; несовместимость не обходится отключением
проверки хешей. Архив кода не заменяет резервную копию Python-окружения.

Полный журнал сжимается фоновым потоком. Очередь ограничена 32 MiB и 32768
записями; потеря входов или обычных событий делает запись непригодной для точного
сравнения и останавливает paper-торговлю. Остаток диска менее 5 GiB также вызывает
остановку. Резерв 20/100/200 GiB — начальное условие, а не обещание размера: частота
рынка меняется. Для проверки нужен дополнительный временный дисковый индекс.
Принудительное закрытие процесса может оставить незавершённый gzip без footer;
такой файл нельзя считать проверенной записью.

## Границы последующей симуляции

Готовая команда проверки воспроизводит **исходный состав** и сверяет каждое
сохранённое событие, сделки, комиссии и баланс. Из сравнения исключены только
операционные `run_summary.latencyMetrics` и `run_summary.recorderHealth`.
Данные читаются потоком, индекс находится на диске и удаляется после проверки.
Ошибки целостности, несовпадение исходников/зависимостей или финансовых результатов
дают отказ, а не успешный отчёт.

Отдельные симуляции четырёх стратегий — следующий шаг после получения и проверки
общей записи. **Эти профили ещё не реализуют такое сравнение.** Для него потребуется
повторная оценка сигналов и исполнений в отдельных портфелях на сохранённых
рыночных событиях; фильтровать только уже совершённые сделки некорректно.
Симуляция ограничена записанными монетами и интервалами подписок: нельзя
восстановить рынок монеты, которую исходный сканер не записывал. Другой состав
позиций также может изменить ротацию монет; это ограничение нужно указать в отчёте.

Час проверяет техническую работоспособность и последствия последней правки.
Двенадцать часов дадут общую рыночную выборку для диагностики стратегий, но не
докажут положительное ожидание или готовность к торговле реальными деньгами.
