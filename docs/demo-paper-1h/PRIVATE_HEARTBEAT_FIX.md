# Приватный Demo WebSocket: heartbeat и диагностика

Исходный прогон: `data/audit-demo-paper-1h-repeat-20260927-2201`, run `2eab3171d9cd40c39671ce22b9daf399`. Start 22:01:47 МСК 27.09.2026; `private_ws_gap` 22:12:06.814; финальное завершение 22:12:18, exit 2. Статус INCOMPLETE, 0 пар, 806 завершённых прогнозов, позиции сверены, funding complete, recorder 3 274 614/3 274 614 строк без drops. Пользователь сообщил, что VPN не менял. Повторное чтение пяти категорий аккаунта подтвердило 0 позиций/заявок; ordinary paper продолжал работать.

Подтверждённая цепочка остановки: `private_stream` перехватил исключение и вызвал `gap("private_ws_gap")`; `Session.gap` закрыл допуск и зафиксировал Stop; Session выполнил финальную сверку. Старый обработчик не сохранял тип исключения, этап и close code. Поэтому из сохранённого журнала нельзя установить серверную причину конкретного разрыва или приписать его VPN.

Найден отдельный воспроизводимый дефект: отсутствовал прикладной JSON heartbeat Bybit. RFC6455 control ping был включён, но не заменял `{"op":"ping"}`. По [документации Bybit](https://bybit-exchange.github.io/docs/v5/ws/connect#how-to-send-the-heartbeat-packet) рекомендуется heartbeat каждые 20 s; неактивный private stream может закрываться через 10 минут с дискретностью проверки около 30 s. Длительность исходного соединения согласуется с этим механизмом. Это обоснованная гипотеза, а не сохранённая причина закрытия сервера.

Изменения:

- JSON ping каждые 20 s независимо от наличия private data; подтверждение только совпадающим req_id. RFC control ping 15 s / timeout 10 s сохранены.
- Отсутствующий/чужой pong не освежает канал: после 10 s вызывается прежняя защитная обработка gap. Heartbeat не передаётся как рыночный факт и не обновляет freshness стакана.
- `private_heartbeat` сохраняет номер и RTT; `private_transport_failure` — этап, тип/цепочку ошибок, числовые close codes и длительность. Тексты исключений, auth, ключи, заголовки и серверные строки не сериализуются.
- Поведение Stop/reconciliation, часовой deadline, профили риска/ML, qty/fee fixes и запрет private mainnet не менялись. Автоматического нового торгового часа нет.

Регрессия до исправления воспроизвела private_ws_gap после виртуальных 600 s. После исправления виртуальные 660 s проходят; потеря pong, неверный req_id, непрерывный поток private data, сохранение событий и редактирование диагностики покрыты тестами.
