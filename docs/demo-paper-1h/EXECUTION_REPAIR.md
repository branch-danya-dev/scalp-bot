# Исправление Demo после фактического отказа ZEC

Источник: сохранённый `audit-demo-paper-1h-20260927-174758`, две пары ZECUSDT. Старый отчёт и raw не изменены. Это отдельный исправляющий этап, не пересчёт доходности.

- Для входа 2.49 и partial 0.74 остаток вычислялся float как `1.7500000000000002`. Demo отклонил target с 10001, после чего штатная защита прекратила входы и закрыла позицию. Теперь физический остаток считается Decimal по дедуплицированным исполнениям; разбиение количества остаётся точным. Неправильный шаг не округляется молча: команда блокируется до сети.
- У первой пары остаток 1.74 сравнивался с float-хвостом. Неизменённый runner повторно отменялся и создавался. Сравнение использует точный остаток и ту же нормализацию цены, что отправка.
- Однозначный отказ create ошибочно превращался в неизвестную заявку при поиске несуществующего order ID. Теперь происхождение такого отказа сохраняется; неопределённые POST/duplicate ошибки по-прежнему требуют reconciliation и не повторяются новым ID.
- При завершении одновременно выполнялись обычный и финальный опросы одного последовательного REST-клиента. В журнале шесть timeout по 15 секунд. Обычный опрос завершается перед финальным, защита продолжает работать. Успешные проверки завершённых неизменённых ордеров сохраняются между ограниченными попытками; новые факты требуют повторной проверки. Все категории аккаунта проверяются на каждой попытке. Бюджеты 15/90/30 секунд не повышены.

Регрессия использует сокращённые реальные планы/исполнения двух пар с provenance SHA исходного журнала. Проверяются 1.75, 1.74, отсутствие повторных замен runner, точное закрытие остатка, определённые и неопределённые отказы, продолжение после прерывания финальной сверки и отсутствие параллельного фонового опроса при shutdown. 69 целевых проверок прошли.

Подключённый preflight 27.09.2026 прошёл: аккаунт Demo, REGULAR_MARGIN, открытых позиций и заявок во всех проверяемых категориях нет. Сам preflight не создавал заявок. Новый запуск теперь явно разрешён последним сообщением владельца. Результаты фактического запуска будут записаны отдельно.

Риск, плечо, partial, стопы, ML V2/.55, паспорт, recorder и проверки свежести не менялись. Прежний прерванный запуск остаётся INCOMPLETE, ML_TRADING_NOT_TESTED. Его превышение latency не объявляется исправленным этими изменениями; 20/5/250 ms остаются прежними.
