# E06: штатный вариант и независимая paper-запись

Подготовлено 2026-09-25. Рабочий сервер по умолчанию продолжает использовать 8s. Штатный параметр `e06_conditional_breakout_hold=false` явно входит в manifest v4; при включении он сокращает sustained hold до3s только при текущих `nearCloses>=2` и `compressedPullbacks>=2`. Иначе используется базовое ожидание8s. Таймер при потере структуры не сбрасывается; retest/flow/response/risk не меняются. Исследовательское runtime-расширение для новых запусков не требуется.

## Запуск

Из `G:\scalp-bot`:

```powershell
.\.venv\Scripts\python.exe scripts/run-e06-paper.py --output data/e06-independent-01
```

Одна команда выполняет последовательно:

1. **30 минут технической paper-записи** двух независимых портфелей на общем потоке. E01 выключен у обоих; E06 выключен в baseline и включён в candidate.
2. Проверку полного input chain/footer, завершения, финансовых журналов, конфигураций и качества записи. Затем **полный replay обоих портфелей** со сравнением каждого события с записанным журналом.
3. Только при успешных проверках — **новый 12-часовой независимый период**, с холодного старта обоих портфелей и неизменными параметрами. Smoke не включается в этот период.
4. Финальный аудит 12h capture. Полное воспроизведение этого большого периода выполняется отдельно после окончания записи.

Общее время — **12ч30мин плюс прогрев, аудит и replay smoke**. Replay вычислительный, а не ожидание новых рыночных данных. Каталог должен быть новым; существующий не перезаписывается. Launcher не запускает веб-сервер. Для наблюдения есть отдельный UI, описанный ниже. Кнопка Start обычного сервера к этому прогону не подключена.

## Наблюдение в UI

В отдельном терминале из `G:\scalp-bot` запустите:

```powershell
.\.venv\Scripts\python.exe tools/e06_monitor/server.py --capture data/e06-independent-01 --port 8001
```

Откройте [монитор эксперимента](http://127.0.0.1:8001/). Это отдельный экран сравнения двух вариантов, не замена основного интерфейса. Прежний UI со свечными графиками, стаканом и управлением сохранён в `scalp_bot/static`; он запускается через `.\scripts\run.ps1` на `http://127.0.0.1:8000/`. Обычный UI работает со своим TradingEngine и не подключается к парным портфелям E06. Запускать его ради просмотра этих же двух портфелей нельзя: он покажет другой экземпляр движка. Долгосрочно нужен общий интерфейс с выбором источника данных; адаптер парной записи к старым графикам пока не реализован.

Основная команда `scripts/run-e06-paper.py` запускается в другом терминале. `--capture` монитора должен совпадать с `--output` прогона. Монитор можно запускать до создания каталога: он не создаёт и не резервирует каталог записи. Можно подключиться и к уже идущей записи. При переходе smoke → replay → independent UI переключается автоматически; результаты smoke не смешиваются с независимым периодом.

Экран показывает два портфеля, капитал/баланс/открытый PnL, изменение капитала, график, позиции со временем снимка, последние 100 закрытых сделок каждого портфеля, таймер периода и готовность рыночных данных. Источник рыночного потока — Bybit, сделки — paper. Сумма net закрытых сделок берётся за полный цикл; частичные выходы повторно не прибавляются. Изменение капитала рассчитывается от записанного начального баланса, открытый PnL — как equity минус balance. Это оценки paper-брокера, а не независимая переоценка исполнения.

Обновление страницы — каждые 2 секунды, с дополнительной задержкой записи/буферизации журналов. При подключении посреди большого прогона монитор читает историю порциями с ограничением объёма. Текущий капитал появляется сразу из хвоста equity; детали позиций и итоговый net закрытых становятся доступны после догрузки соответствующего журнала. График прореживается и сохраняет начало периода. Отдельные позиции могут иметь более старую оценку, чем сводный equity; время снимка отображается в таблице.

Отсутствие свежих записей более 30 секунд отмечается отдельно от ошибки прогона. `failure.json` означает сбой, `result.json` — записанный период, `completed.json` в корне — завершение цепочки. У этапа replay нет отдельного heartbeat: UI показывает наличие его артефактов, а не подтверждает, что процесс ещё работает. Детальный ход аудита/replay остаётся в терминале. UI не заменяет аудит и не выставляет допуск в production.

Монитор находится в `tools/e06_monitor`, использует стандартную библиотеку Python, не импортирует торговый движок, не читает `.env`, не подключается к Bybit и не изменяет запись. Он доступен только на loopback, без внешних CDN. Код и конфигурации замороженного эксперимента для подключения UI менять не нужно. Страница предназначена для наблюдения; запуск/остановка записи остаются в терминале. Ctrl+C в терминале монитора останавливает только UI, в терминале прогона — сам прогон. Закрытие вкладки ни один процесс не останавливает.

По умолчанию монитор использует порт 8001, порт 8000 остаётся основному UI. Если 8001 занят, укажите другой `--port`. Монитор не останавливает другие процессы и не занимает их порт. Для просмотра завершённого отдельного периода допустим путь непосредственно к папке с `equity.jsonl` и двумя журналами событий.

Проверки монитора: `tests/test_e06_monitor.py` — незавершённые строки, частичные выходы, финансовые метрики, переходы этапов, задержки, ограничение истории и API без записи. Отдельно проверяется отображение сохранённого журнала в браузере.

Проверка готовности без сети и без создания записи:

```powershell
.\.venv\Scripts\python.exe scripts/run-e06-paper.py --output data/e06-independent-01 --check
```

Для отдельного smoke можно добавить `--phase smoke`. Для последующего независимого периода с уже завершённым smoke:

```powershell
.\.venv\Scripts\python.exe scripts/run-e06-paper.py --phase independent --smoke data/e06-smoke-only/smoke --output data/e06-independent-next
```

В этом случае профили, текущий source/runtime и весь smoke проверяются заново, включая полный replay. Указанный пример предполагает, что отдельный smoke был запущен с `--output data/e06-smoke-only --phase smoke`.

## Фиксация эксперимента

Профили: `configs/e06-smoke.json` и `configs/e06-independent-12h.json`. Они отличаются только меткой и длительностью. `.env`, сохранённые API-ключи и переключатели UI не используются. На биржу идут только запросы рыночных данных; позиции и исполнения — paper.

До начала сохраняется `protocol.json`: правила, критерии оценки, SHA-256 source и профилей/launcher/replay/audit. Содержимое профилей и инструментов архивируется в `protocol-sources.zip`. Каждый период получает собственный `source-at-capture.zip`: все manifest source-файлы с проверенными hashes, без `.env` и секретов. Код/профили нельзя менять между smoke и независимым периодом или во время записи; изменение аннулирует автоматический переход/результат. Source/runtime guards остаются включёнными.

Формат новой E06-записи — `paired-feed-v3` с явным `experiment=E06`; конфигурации обоих manifests различаются **только** `e06_conditional_breakout_hold`. E01 сохраняет прежний режим по умолчанию. Валидация исторических manifests v3 сохраняет прежний набор полей; их source/runtime требования не ослабляются.

## Ресурсы и остановки

На диске требуется минимум **100 GiB свободного места** для автоматического/12h запуска; после smoke —90GiB. Это резерв на основании прежнего потока около3GB за30мин, а не гарантия максимального размера. Во время записи проверяется остаток5GiB раз в минуту. Поток ограничен5млн inputs для smoke и60млн для12h; превышение завершает запись как невалидную.

Сбой источника, reconnect, backpressure, незавершённый портфель, несовпадение source/профиля или недостаток диска останавливают цепочку. Неудачный smoke не запускает12h. Автоматических повторов, продолжения после разрыва и выбора удобного конца по PnL нет. Ctrl+C также сохраняет failure; не считать такой период завершённым независимым сравнением.

Для сопоставимых условий оставить компьютер работающим без сна и использовать обычную конфигурацию сети, на которой будут идти будущие запуски. Не переключать VPN в процессе записи. Во время подготовки локальная проверка обнаружила около810GiB свободного места; сам launcher перепроверяет место перед запуском.

## Критерии оценки, заданные до новых данных

Главная метрика — разница полного net после fees/funding, с учётом уже встроенного в fills проскальзывания. Контроль и кандидат имеют одинаковый начальный капитал и модель исполнения.

- Период фиксирован:12h; шесть последовательных блоков по2h от общего Start. Сделки относятся к блоку по времени входа; исход может завершаться позже.
- Минимальное покрытие для решения о следующей валидации:30 уникальных setup identities с различающимся допуском или временем входа, не менее3 инструментов и3 блоков. Повторные evaluations и изменения только размера из-за капитала не считать новыми независимыми случаями.
- Условия положительного результата для следующего этапа: net кандидата положителен; прирост не меньше0.1% начального капитала (1USDT при1000); sampled maxDD кандидата не выше110% контроля. При нулевой просадке контроля кандидат также должен иметь нулевую.
- Недостаточное покрытие означает **недостаточно данных**, даже при положительном PnL. Показать концентрацию на отдельных сделках/инструментах/блоках и неопределённость; нельзя делать статистическое заключение только по этим минимальным количествам. Параметры на этом периоде не настраивать и не повторять его до получения плюса.
- До оценки обязателен полный replay независимого периода. Даже выполнение условий допускает лишь следующую проверку переносимости/исполнения, не live и не production-ready. Smoke-03 и технический smoke — development/технические данные.

## После завершения

Главные файлы в `data/e06-independent-01`: `protocol.json`, `protocol-sources.zip`, `completed.json`; папки `smoke`, `smoke-replay`, `independent`. В каждом capture: feed, оба журнала событий, equity, transport/performance, manifests в result, audit и source archive. При сбое — failure.json в соответствующей папке и в корне цепочки.

Команда для полного воспроизведения нового независимого периода без сети:

```powershell
.\.venv\Scripts\python.exe scripts/replay-paired-capture.py data/e06-independent-01/independent --output data/e06-independent-01/independent-replay
```

Replay читает журналы потоково, хранит только закрытые сделки и сравнивает все события двух портфелей. Не использовать старый in-memory runner для многомиллионного периода. Если после записи код изменён, сначала восстановить соответствующий source из архива и указать его через `--source-root`; guard не отключать.
