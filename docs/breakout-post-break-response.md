# E03: измерение реакции после начала пробоя

Дата: 2026-09-25. Продолжение [разбора признаков входа](breakout-entry-evidence.md). Этап — наблюдение, без изменения допуска. Данные smoke-03 уже исследованы и не являются holdout.

## Определение измерения

`scripts/replay-breakout-response.py` воспроизводит исходную стратегию из проверенного captured source. После каждого вызова evaluate внешний наблюдатель читает состояние стратегии и возвращает исходное решение без изменений.

Якорь — **book mid при создании текущего `break_started_at`**. Это момент, когда стратегия начала считать подтверждение, а не первый физический тик за уровнем, первое записанное BREAK поколения или время ARMED. Формула:

```text
postBreakResponseBps = direction × (currentBookMid / anchorBookMid − 1) × 10000
direction = +1 для long, −1 для short
```

Оба конца измерения используют одну цену — mid стакана, которую использует стратегия при наличии книги. Якорь определяется по поколению уровня и точному `break_started_at`, заменяется при новом эпизоде, удаляется при сбросе. Если наблюдатель не видел создание эпизода, цены нет или ещё не было более позднего наблюдения, результат остаётся неизвестным (`null`). Нельзя ретроспективно подставить цену первого доступного позднего наблюдения.

Это **не tape-response**. Наблюдатель не использует сделки, поэтому старый trade с поздним получением не может изменить выбранный якорь. Market-data freshness и clock-проверки остаются штатными. Значение mid не является исполнимой доходностью и не учитывает спред/комиссии.

Исходный rolling response считается по сделкам у уровня, новый — по mid от начала эпизода. Поэтому различие двух чисел отражает **и окно, и источник цены**; его нельзя приписать только времени. Если новое измерение станет правилом, этот контракт должен входить в дизайн E03 явно. Смена источника пока не меняет торговлю.

Сохраняются все доступные наблюдения активных эпизодов того же поколения, а не только изменения решений или первые 100 секунд. Отдельно записаны rolling/post-break значения, прохождение прежнего порога 5 bps, исходное действие и режим подтверждения. Счётчики evaluations не являются числом независимых возможностей.

## Сверка неизменности портфелей

Отдельно воспроизводятся 8s и уже проверенный 3s-портфель. Значение hold задаётся при создании движка; новые параметры стратегии не вводятся. E01=false на обеих сторонах.

Каждое выходное событие сравнивается с соответствующим прежним журналом, включая timestamp, решения, арбитр, риск, открытие и закрытие позиций. Исключения прежние: случайный `manifestId` и неповторимые process-wide `run_summary.payload.latencyMetrics`. Дополнительно проверяются SHA-256 контрольного журнала, полный input chain/footer, число входов, конечный баланс, все закрытые сделки и отсутствие позиций/pending. Captured source и runtime проходят штатные guards.

Запуски:

```powershell
.\.venv\Scripts\python.exe scripts/replay-breakout-response.py data/e01-smoke-03 --feed-name feed-sealed-prefix.jsonl --source-root data/e01-smoke-03/captured-source --hold 8 --output-directory data/e01-smoke-03/response-8s-repeat
.\.venv\Scripts\python.exe scripts/replay-breakout-response.py data/e01-smoke-03 --feed-name feed-sealed-prefix.jsonl --source-root data/e01-smoke-03/captured-source --hold 3 --output-directory data/e01-smoke-03/response-3s-repeat
```

Каталог должен быть новым. Артефакты: scenario.json с определением до replay, response.jsonl со всеми измерениями и result.json только после успешной сверки. При ошибке выполнения сохраняется failure.json. Проверенные входные журналы не перезаписываются.

## Проверки реализации

3 теста прошли: смена эпизода/поколения и знак short, отсутствие данных без выдуманного якоря, полный fixture replay с точным сравнением всех событий. Production source, captured source и рабочий профиль не менялись. Полный suite не повторялся.

Полные запуски завершены успешно. Каждый прочитал **1091002 inputs**, общий hash `ca72cf556d675ad1068a5abee2ac05615897109a2dd44ef97ad34ee6f4301869` совпал. Источник `02fdcafeeb168a4b972a0ac6c58a87f7b4b53ccf77a3bd3fa3b89b2ad8136416` не изменялся.

Количество эпизодов различается из-за прежних различий в открытии/потреблении setups между портфелями. Счётчики 286/217 включают WAIT и связанные повторные evaluations; это не число ошибочных сделок и не оценка частоты ложных входов.

## Наблюдения перед фактическими входами

Сопоставляются последние готовые сигналы того же поколения до открытия. Числа ниже относятся к сигналу; короткая задержка до исполнения сохраняется отдельно в разборе. Экстремумы рассчитаны только по observations между созданием якоря и сигналом, без последующей цены.

| Портфель / сигнал | Rolling response, bps | Post-break mid response, bps | Максимальный post-break response до сигнала, bps |
|---|---:|---:|---:|
| 8s / BTC short | 5.1783 | **0.0239** | 1.0051 |
| 3s / BTC short | 5.2261 | **0.0000** | 0.0000 |
| 3s / ENA long | 21.5905 | **11.9830** | 16.7762 |
| 3s / ZEC short | 33.5919 | **−1.6443** | 1.2648 |

У BTC скользящий показатель допускает sustained-confirmation при почти неподвижном mid в текущем эпизоде. Но **это не объясняет ложный ENA**: у него после запуска таймера действительно было достаточное движение, больше прежнего порога 5 bps. Успешный ZEC к сигналу немного откатился относительно первой mid-цены подтверждения. Даже максимальное наблюдавшееся продвижение в этом эпизоде не достигало 5 bps.

Следовательно, простая замена rolling-показателя на `postBreakResponseBps >= 5` на этих готовых сигналах убирает BTC и ZEC, оставляя ENA. Использование достигнутого максимума вместо текущего response при том же пороге не меняет этот локальный вывод. Это **проверка признаков**, не пересчитанный портфель: нельзя складывать PnL оставшихся сделок и выдавать это за replay нового правила.

Отсутствие нового продвижения не равно ложному пробою. Цена могла уже пройти значительную часть движения к моменту запуска таймера и затем удерживаться за уровнем. Для ZEC это совместимо с наблюдениями, но универсальная причинная модель тремя сделками не установлена. Не следует двигать якорь/порог до тех пор, пока на этой записи получится удобная классификация.

## Решение и следующий шаг

**Не внедрять E03 как обязательные дополнительные 5 bps от запуска таймера.** Инструмент измерения полезен, торговая полезность этой простой замены не подтверждена. Рабочие hold 8s, stop limit 0.6% и E01=false сохраняются.

Следующая development-гипотеза — **E06: условное ускорение структурно подготовленного пробоя**. Проверять один заранее заданный вариант:

- Контроль: прежние 8s для sustained-confirmation.
- Вариант: 3s только когда в текущем evaluate присутствуют оба уже существующих структурных балла (`nearCloses >= 2` и `compressedPullbacks >= 2`); иначе прежние 8s. Это не признаки первого BREAK поколения. Условие пересчитывается при каждом evaluate; потеря признака возвращает требование 8s, время текущего эпизода не обнуляется. Ретест сохраняет прежнюю независимую логику.
- Поток, rolling response/порог 5 bps, арбитр, стоп, размер риска, расходы и E01 flag остаются прежними. Не добавлять одновременно фильтр силы flow, post-break response или новый target.
- Перед измерением эффекта подтвердить точное воспроизведение контроля новым инструментом. Затем полный независимый портфель от холодного старта, все новые/исчезнувшие/сдвинутые сделки, net/fees/DD и подписки. Проверить побочные эффекты вне ENA/ZEC.
- Не перебирать другие значения времени/числа структурных баллов на smoke-03. Даже положительный результат этого варианта будет development-результатом; нетронутая запись обязательна для продвижения.

Основание ограниченное: на уже известных сигналах эта комбинация оставляет ранний ZEC и не ускоряет ENA без структуры; убыточный BTC она тоже сохраняет. Она не обещает убрать все ложные сделки. На момент фиксации гипотезы E06 ещё не был реализован. Последующая реализация и полное сравнение описаны в [отчёте E06](e06-conditional-breakout-hold.md).
