# E06: условное ускорение подготовленного пробоя

Дата: 2026-09-25. Development-эксперимент на smoke-03. Дизайн заранее зафиксирован в [отчёте E03](breakout-post-break-response.md). Новые пороги не подбираются.

Последующий шаг выполнен: [штатный default-off E06 и команда независимой записи](e06-independent-capture.md) подготовлены. Новая рыночная запись ещё не запускалась.

## Изменение

Контроль сохраняет 8s для sustained-confirmation. Кандидат использует 3s, если **в текущем evaluate** есть оба существующих структурных балла: `nearCloses >= 2` и `compressedPullbacks >= 2`. Иначе требуются 8s. При потере структуры таймер эпизода не обнуляется. Новое правило не заменяет проверки потока, направленной реакции цены и риска. Ретест сохраняет собственную логику.

Это не универсальный фильтр ложных входов. В частности, убыточный BTC имеет оба структурных признака. Проверяется узкий вопрос: удаётся ли сократить задержку для подготовленного пробоя без побочного ускорения входов вроде ENA без структуры.

## Реализация и происхождение кода

`scripts/compare-conditional-breakout-hold.py` реализует правило как **исследовательское расширение captured strategy**, вне рабочего сервера. Один native evaluate вызывается ровно один раз на собственном сохраняемом состоянии каждого портфеля. После штатного расчёта pressure расширение выбирает sustained hold; исходный pressure score и его составляющие возвращаются без изменений. Перед каждым evaluate и в finally hold возвращается к 8s, поэтому другой символ не наследует чужую ветку, включая случай исключения.

Captured source и рабочие настройки не редактируются. Source/runtime guards записи остаются включёнными. Нельзя считать исходный engine manifest полным описанием кандидата: он описывает **базовый код/конфигурацию**, поверх которых работает исследовательское правило. Полное описание эксперимента — `baseManifest` вместе со `scenario`, её SHA-256 и SHA-256 runner/использованных helpers. Сценарий сохраняется до первого input; изменение этих файлов во время выполнения аннулирует результат. Этот исследовательский вариант не подключён к live-серверу.

## Условия признания сравнения

- Оба портфеля идут от холодного старта на полном одинаковом input chain, E01=false.
- Контроль с тем же расширением, но выключенным правилом, сравнивает каждое output event с исходным baseline. Исключаются только прежние случайный manifestId и process-wide latencyMetrics в run_summary. Финальные trades, balance и выборочный DD должны совпасть.
- Кандидат проходит обычные strategy → arbiter → risk → broker → exit со своим капиталом и состояниями. Закрытые сделки сверяются с балансом; позиции/pending должны отсутствовать, жизненный цикл start/summary/stop — завершиться.
- Список активаций/деактиваций кандидата должен совпадать с записанным контролем: иначе покрытие подписками не подтверждено и результат отклоняется.
- Расчёты могут выполняться одновременно, но результат кандидата имеет статус `candidate_executed_pending_control`. Отдельный finalize допускает сравнение только после полной успешной parity контроля, совпадения input/code/config/rule и повторного чтения candidate ledger с проверкой trades/count/net. Частичного контроля недостаточно.
- Выборочный DD использует equity на прежних health/stop-срезах; это не tick-exact оценка.

Тесты проверяют границы структурных условий, возврат к 8s, сохранение таймера, изоляцию символов, восстановление после исключения, настоящий retest-контракт и полный fixture control/candidate/finalize. Подмена сохранённого сценария отклоняется.

## Воспроизведение

Каждый каталог расчёта должен быть новым. Финальное сравнение создаётся отдельным файлом без перезаписи:

```powershell
.\.venv\Scripts\python.exe scripts/compare-conditional-breakout-hold.py data/e01-smoke-03 --feed-name feed-sealed-prefix.jsonl --source-root data/e01-smoke-03/captured-source --mode control --output-directory data/e01-smoke-03/e06-control-repeat
.\.venv\Scripts\python.exe scripts/compare-conditional-breakout-hold.py data/e01-smoke-03 --feed-name feed-sealed-prefix.jsonl --source-root data/e01-smoke-03/captured-source --mode candidate --output-directory data/e01-smoke-03/e06-candidate-repeat
.\.venv\Scripts\python.exe scripts/compare-conditional-breakout-hold.py data/e01-smoke-03/e06-candidate-repeat --mode finalize --control-directory data/e01-smoke-03/e06-control-repeat --output-directory data/e01-smoke-03/e06-candidate-repeat
```

Артефакты каждого запуска: scenario.json, hold-decisions.jsonl, equity.jsonl, result.json после успешного выполнения. Кандидат дополнительно пишет полный candidate-events.jsonl, finalize — comparison.json. Ошибочный запуск сохраняет failure.json и не допускается к сравнению. Исходная запись не изменяется.

## Результат полного сравнения

Запуски `e06-control-01` и `e06-candidate-01` завершены; finalize выдал `E06_development_comparison_validated`. Каждый обработал все **1091002 inputs**, общий hash совпал с capture. Контроль точно воспроизвёл **93755 output events**, все сделки, баланс и выборочный DD исходного baseline. Кандидат сохранил 93746 событий; повторная сверка persisted ledger/count/trades/net прошла. Позиции/pending закрыты, подписки совпали, failure.json отсутствуют.

| Метрика | Контроль 8s | E06: условные 3s/8s |
|---|---:|---:|
| Закрытые сделки | 5 | 6 |
| Net после комиссий, USDT | +2.02239 | **+7.81893** |
| Комиссии, USDT | 6.46801 | 6.94480 |
| Выборочная максимальная просадка, USDT | 14.08724 | 12.33226 |

Разница net **+5.79655 USDT**. Контроль занял 774.03s, кандидат 747.30s; вычисления шли независимо одновременно, вывод принят только после завершения обоих. Контроль провёл 60404 расчёта pressure с hold8; кандидат — 40936 с hold8 и 17468 с hold3. Это связанные evaluations, не независимые сделки.

Исчезнувших сделок относительно контроля нет; единственный добавленный setup — ZEC. У него notional616.73112 USDT, net+5.74821. XPL/ONDO открываются в прежнее время, но после прибыли ZEC получают немного больший размер. BTC остаётся убыточным: −1.07696 против −1.07816. Сопоставление по symbol/strategy/side/setupId и проверка суммы вкладов сохранены в `e06-candidate-01/attribution.json`, вместе с hash финального comparison.

Дополнительный ENA long breakout из прежнего варианта «3s для всех» отсутствует. На точно том же evaluate `monoNs=454308770700900` E06 имеет nearCloses=0, compressedPullbacks=0, hold8, action=wait. ZEC на `454395141985500` имеет 5/2, hold3 и получает short-сигнал. Это полный результат независимого портфеля, а не ручное удаление ENA из старого журнала.

**99.17% прироста приходится на одну дополнительную сделку ZEC.** Остаток — её влияние на капитал и небольшой сдвиг BTC. Эта атрибуция не заменяет отдельный replay «без ZEC». Снижение выборочной просадки также относится только к этой записи, не обещает улучшения в других рыночных условиях.

## Решение и продолжение

E06 прошёл development-проверку и имеет основание для **независимой проверки на новых данных**. Рабочий профиль не переключается: smoke-03 использовался для выработки гипотезы, поэтому не является доказательством вне выборки.

Следующий инженерный шаг — перенести ровно это правило в штатный отключённый по умолчанию вариант с явным параметром в manifest, тестами соответствия исследовательской реализации и независимыми paper-портфелями контроля/кандидата. E01 оставить выключенным на обеих сторонах; параметры не подбирать по старой записи. После технического smoke зафиксировать новый протокол и собрать нетронутый период. До подтверждения переносимости нельзя включать правило для реальных средств или объявлять production-ready.

Проверки: **5 профильных tests passed за4.89s**, включая4 новых E06-теста и предыдущий full-hold portfolio test. Реальный полный контроль, candidate и finalize прошли. Рабочий production source не менялся, полный suite не повторялся. Diff check чист.
