# Обычный часовой paper-прогон

Для нового запуска с последующей симуляцией используйте [два профиля полной записи](paper-capture-profiles.md). Описанный ниже прежний launcher сохраняется для обычного наблюдения, но не включает полный журнал всех входов engine.

Обычный запуск одного бота в основном UI для разбора входов, выходов и отказов. Парные прогоны отложены. Данные рынка поступают с Bybit; сделки и баланс моделируются локально. [Последняя запись разобрана](paper-current-1h-results.md). Добавленная [свечная beta](price-action-hypothesis-beta.md) по умолчанию выключена; включение до Start переводит запуск в диагностику нового набора стратегий.

Из корня проекта:

```powershell
.\scripts\run-paper-1h.ps1
```

Launcher выполняет тесты и проверку подключения к Bybit, затем открывает сервер на **http://127.0.0.1:8000/**. В браузере остаётся основной интерфейс со свечами, стаканом, позициями и разбором сделок. Дождаться готовности рынка и нажать **Start**. Час отсчитывается с этого нажатия, а не с запуска команды. Стратегии и настройки во время записи не переключать.

Через 3600 секунд бот отменит оставшиеся заявки, закроет paper-позиции с причиной `duration_elapsed` и запишет `run_summary`. UI останется доступен. После появления итогов завершить сервер через Ctrl+C и дождаться возврата приглашения терминала: это завершает запись и фоновые задачи. Повторно Start в этой сессии не нажимать.

## Настройки

Профиль `.env.research-1h` загружается поверх текущего `.env.example`; метка — `paper-current-1h`. Правила входа, риска и выхода обычного сервера сохранены. Меняются длительность и частота диагностических снимков: research 3s с delta-лентой, replay 5s при активности / 20s в ожидании. События сделок и исходные коды причин сохраняются отдельно от периодических снимков.

С 26 сентября текущий код включает [исправление часового veto для подтверждённого локального пробоя](breakout-hourly-context.md). Оно применяется при обычном запуске после перезапуска сервера. Версия кода фиксируется manifest; результаты предыдущей записи не описывают это новое поведение.

| Модуль | Поведение в этом запуске |
|---|---|
| Пробой уровня | Включён, может открывать сделки |
| Отбой от уровня | Включён, может открывать сделки |
| Трендовый откат | Отключён, как в обычном профиле |
| Плотности стакана | Дополнительные признаки, без собственных входов |
| Гипотеза цены · BETA | Выключена; отдельная опция UI, правила и порядок отдельной записи описаны в её инструкции |

E01/E06 выключены. Это один торговый движок и один портфель. Локальный `.env` и остаточные `SCALP_*` от других запусков не меняют профиль; launcher сохраняет только необязательные ключи процесса для чтения комиссии и восстанавливает прежнее окружение после завершения. Фактическая несекретная конфигурация записывается в manifest события `bot_started`.

В обычном `.env.example` `enforce_min_net_profit_gate=false`. Поэтому найденное в парном E06 отключение partial порогом net 1 USDT нельзя автоматически приписывать этому запуску: сначала проверяем manifest и реальные планы сделок.

## Что сохраняется и что разбирать

- `data/sessions/session-<UTC-время>.jsonl` — исходная сессия: manifest, решения, отказы, сделки, частичные выходы, MFE/MAE, комиссии, рыночные снимки и итог.
- `data/run-logs/paper-current-1h-<время>.log` — терминальный журнал, включая ошибки запуска и работы сервера.
- Существующие сессии не удалять. Для следующего запуска создаются новые имена файлов.

UI показывает отдельные причины: стоп, цель, отсутствие продолжения, возврат за уровень, потеря контекста, завершение часа. Исходный код доступен при наведении на причину. Отсутствующая причина помечается «Причина не записана», незнакомый код отображается явно и остаётся в журнале. «Выход» в ленте — тип события; конкретная причина указана рядом.

После часа проверяем полноту записи, затем каждую закрытую сделку: причина выхода, gross/fees/net, достигнутые MFE/MAE, частичная фиксация, прибыль перед возвратом в убыток. Принудительные закрытия по таймеру учитывать отдельно от решений стратегии. По входам — какие стратегии дали сигнал, что было допущено или отклонено и почему. После этого выбираем конкретное исправление. Один час предназначен для диагностики, а не доказательства прибыльности.
