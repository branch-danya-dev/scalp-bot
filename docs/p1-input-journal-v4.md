# P1-02 v4: периодические вызовы, UI и восстановление потоков

25 сентября 2026. Writer использует `replay-input-v4`, validator читает v1–v4 с coverage соответствующей версии. Capture остаётся экспериментальным API `capture_inputs=True`, по умолчанию выключенным. Полного offline dispatcher пока нет; `parityReady=false` даже при корректной структуре.

## Новые наблюдения

- `source_await.failed`: расширение диагностики scanner/bootstrap — исходные errorType/errorMessage, которые уже использовались в error outputs. [Поведение и ограничения](p1-offline-source-diagnostics.md).
- `source_await`: добавочное расширение v4 — wait/ready/cancelled/raised вокруг scanner и bootstrap, а также [clock REST-await](p1-offline-clock-await.md). ID/source/symbol связывают границы. Clock ready включает доставку REST-ошибки, результат определяется следующим clock_sample/error. [Контракт scanner/bootstrap](p1-offline-source-await.md).
- `context_await`: добавочное расширение v4 — начало batch, запуск проверки/загрузки каждого symbol, готовность batch или отмена. [Контракт и replay](p1-offline-context-await.md).
- `dispatch`: начало ожидания, пробуждение или отмена для clock/scanner/context/arbiter loops и paper timer. ID связывает пару событий; сохраняются источник и задержка. Длительные loop scopes фиксируют связанные чтения часов.
- `external`: запрос `public_state` с исходным selectedSymbol, до выбора запасного инструмента. Вложенный `market_health` имеет свой scope: UI читает часы и может влиять на состояние допуска.
- `service`: вызовы start/close инфраструктуры, отдельно от операторского Start/Stop торговли. Валидатор проверяет форму этих событий; полная проверка service lifecycle ещё не реализована.
- `transport`: connecting, subscription_sent, fault/cancelled, drained; номер попытки, workerId, topics, тип ошибки и число удалённых из очереди сообщений. `subscription_sent` означает отправку запроса, а не подтверждение подписки биржей. Текст сетевой ошибки не копируется.
- `policy_snapshot`: режим и полный разобранный manifest загруженной research policy, fingerprint содержимого и ссылка на hash исходного файла. Восстановление policy не требует чтения исходного файла.

## Переподключение и стаканы

Каждое событие transport содержит полное состояние fast/deep OrderBookState: depth, synced, updateId, seq, все bids/asks. workerId различает повторный запуск инструмента; topics разделяют каналы. Состояния записываются такими, какими их видит обработчик, без искусственного сброса или усечения глубины.

`drained` записывается после остановки обработчика очереди и удаления оставшихся сообщений. Существующая задержка перед cleanup при сетевой ошибке сохранена: callback может обработать сообщения до завершения cleanup. Формат фиксирует этот порядок, но сам по себе не доказывает корректность восстановления рыночного допуска.

Validator проверяет переходы попыток, запрещает reconnect до drained предыдущей попытки и незавершённые попытки перед footer. Для dispatch проверяются уникальные ID, совпадение источника/задержки и завершение ожиданий. Причинные scopes и строгая последовательность clock reads сохраняют контракт v3.

## Policy и provenance

Snapshot привязан к capture manifest по mode, sourceFileSha256 и policyFingerprint. Content hash проверяет разобранный manifest. SourceFileSha256 остаётся ссылкой на исходные байты: из разобранного JSON нельзя восстановить исходное форматирование и повторно проверить raw-file hash. Активный manifest проходит валидацию ResearchPolicyRuntime. Отсутствие snapshot отмечается в missingCoverage; отчёт содержит policySnapshotChecked.

## Проверка и ограничения

Тесты покрывают ожидание/отмену, UI scopes, сетевую ошибку и reconnect без реальной сети, сохранение обоих стаканов, восстановление policy без чтения файла, нарушение transport lifecycle, неверную привязку policy и совместимость v3.

Полный набор: **609 passed**, 33.41 секунды в чистом окружении. Добавлены десять тестов v4.

Нагрузочная стоимость полной записи стаканов и clock reads ещё не проверена. Очередь recorder ограничена; пропуски делают hash/sequence chain непригодной для воспроизведения. Структурная проверка не подтверждает полноту всех возможных внешних воздействий или совпадение торговых результатов.

Следующий инкремент — offline dispatcher с запретом сети и системного времени, затем сравнение решений, отказов, intents, fills и PnL общего движка. Новый длительный пользовательский прогон до готовности этого пути не требуется. P0 recovery stress и эксперимент E01 остаются открытыми; торговые правила и профиль этим изменением не менялись.
