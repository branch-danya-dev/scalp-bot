# E01 smoke-03: завершённое окно и ошибка записи при остановке

Дата разбора: 2026-09-25. Артефакты: `data/e01-smoke-03`. Торговое окно 1800.01 s. Это технический paper smoke, не доказательство прибыльности и не допуск к production.

## Целостность

Оба портфеля завершили работу и закрыли позиции. Однако исходный `feed.jsonl` НЕ проходит строгую проверку: после корректного footer дописаны 17 market_message. Все имеют один sequence 1091003 и previousHash, равный финальному hash. Они появились после stop, когда comparison уже finished; применение отвергалось до изменения состояния, но запись input выполнялась раньше этой проверки.

Исходные файлы сохранены без изменений. `feed-sealed-prefix.jsonl` — отдельная побайтовая копия до первого footer включительно (1246164381 байт). `recovery.json` описывает операцию и все исключённые строки. Это восстановление завершённой записи, не удаление плохого участка торгового окна.

До изменения production-кода выполнен `scripts/audit-e01-capture.py` с явным `--feed-name feed-sealed-prefix.jsonl`. `analysis.json` подтверждает все 1091002 входа по sequence/hash/footer, соответствие source/runtime, конфигураций и финансовых журналов. Общий hash: `ca72cf556d675ad1068a5abee2ac05615897109a2dd44ef97ad34ee6f4301869`. Конфигурации различаются только E01 flag. Конечные открытые позиции: 0/0. Полный повтор стратегии на этом файле НЕ выполнен. После исправлений source guard закономерно отклоняет старый capture в новом checkout; для повторного исполнения нужна исходная версия, обход guard недопустим.

Для будущего воспроизведения сохранён `source-at-capture.zip`: 68 файлов исходников и зависимостей из manifest. Две изменённые в этом инкременте версии восстановлены обратным применением правок только в архиве; SHA-256 каждого файла точно совпал с hash capture. Текущий рабочий код не откатывался. Архив не включает секреты, окружение или рыночные данные.

## Данные и нагрузка

- Внутри завершённой записи 1078099 market inputs; transport faults/backpressure отсутствуют.
- Максимальная задержка очереди 426.20 ms при неизменном пределе 500 ms; максимальная глубина 281. Верхние границы квантилей задержки: p50 5 ms, p95 169 ms, p99 236 ms (корзины по 1 ms).
- Clock: 118 принятых из 313 проб; 194 отклонены по RTT, одна по uncertainty. Медиана RTT 439.53 ms.
- После Start 118 из 6157 health-снимков имели synchronization_expired. По интервалам между снимками это около 29.91 s / 1800 s (1.66%). Это защитная блокировка новых входов; по этим данным нельзя определить число упущенных прибыльных сделок или причину сетевой задержки.
- Один успешный получасовой интервал не подтверждает устойчивость на 72 часа. Исходные журналы занимают около 2.8 GB; большой standalone replay пока хранит outputs в памяти.

## Исправления и дальнейший шаг

LiveSmoke закрывает приём inputs после stop, до finish/footer; поздние callbacks проверяют closing под общей блокировкой и ничего не дописывают. Владение двумя WebSocket-задачами сохраняется до завершения обеих, включая отмену/ошибку одной из них. Добавлены тесты поздних callbacks и завершения дочерних потоков; строгая проверка хвоста сохранена.

Добавлен потоковый аудит capture и ledger без повторного исполнения стратегий. Следующий приоритет — анализ уникальных breakout-кандидатов и различающихся допусков на уже собранных данных, затем суточный отчёт и ограниченное по памяти воспроизведение. Новый рыночный прогон для этого анализа не нужен. Перед 72h остаются проверка исправленного завершения в живом запуске, оценка хранения/нагрузки и воспроизводимость. `profitabilityProven=false`, `parityReady=false`, `longRunReady=false`.

Проверки: 33 профильных теста; полный набор **806 passed за 127.94 s** с `SCALP_DISABLE_DOTENV=1`, без pytest cache. Diff check проходит. Новый сетевой прогон агент не запускал.
