# E01: технический парный прогон на 30 минут

Цель — проверить сбор общего живого потока и независимую работу двух paper-портфелей. Это ещё не 72-часовой эксперимент на прибыльность. Baseline сохраняет текущий допуск breakout перед чужим препятствием; candidate включает запрет. Остальные настройки одинаковы.

Автоматические проверки после второго smoke: 799 тестов прошли при отключённой загрузке .env. Синтетический интеграционный тест проверяет реальную breakout-стратегию, сбор/завершение записи и точное воспроизведение сделок/net; отдельно проверяются разрыв потока, повреждение/усечение файла, подмена конфигурации, union подписок, обновление свечей, независимость/current-tick flow и неизменность расчётов после оптимизации. Эти проверки не заменяют сетевой smoke.

## Запуск

Из корня `G:\scalp-bot`:

```powershell
.\.venv\Scripts\python.exe scripts\run-e01-smoke.py --profile configs\e01-smoke.json --output data\e01-smoke-03
```

Торговое окно — 1800 секунд после готовности рынка; предварительный сканер, загрузка свечей и ожидание синхронизации занимают дополнительное время. Скрипт сам завершает оба портфеля. Каталог результата должен быть новым; для последующего повторения укажите `data\e01-smoke-04`.

Первый smoke остановлен по backpressure примерно через 24 минуты: [разбор записи](e01-smoke-01-results.md). Профиль v2 снижает частоту повторных диагностических снимков, включает приращения ленты в снимках и запрашивает clock sample раз в 5 секунд. Торговые пороги, полный входной поток и предел задержки 500 мс сохранены. Влияние исправлений на живую нагрузку нужно проверить повторным запуском.

[Второй smoke](e01-smoke-02-results.md) остановлен через 16 минут из-за отставания fast ETH на 523 мс. В версии v3 оптимизированы вычисление окон ленты, повторное использование текущего flow внутри одной оценки и копирование входов. На одинаковом фрагменте реальных данных время обработки уменьшилось на 23.8% при совпадении всех выходных событий. Сетевое завершение ещё не подтверждено; новые торговые правила не вводились.

Это отдельный процесс без веб-интерфейса и кнопки Start. Обычный сервер запускать не требуется. Используется JSON-профиль плюс значения по умолчанию из текущего Settings. `.env`, переменные окружения с настройками и API-ключи не читаются. Комиссии берутся из настроек; запросов к приватному API и размещения реальных ордеров нет. Исторические `.env.research-*` не подмешиваются: этот smoke не является повторением их конфигурации.

Запускайте в тех сетевых условиях, в которых планируете основной эксперимент. Не меняйте сеть/VPN во время записи. Код и профиль в процессе прогона не изменяйте.

## Что сохраняется

- `feed.jsonl`: полная публичная конфигурация, версии кода/окружения, общие входы, последовательность и цепочка хешей; завершающая запись только при успешном окончании.
- `baseline-events.jsonl`, `candidate-events.jsonl`: полные события каждого портфеля. В памяти остаётся только журнал закрытых сделок для финансового отчёта.
- `equity.jsonl`: баланс, оценка equity, число открытых позиций и готовность рыночных данных на общих контрольных точках.
- `transport.jsonl`: подключения и диагностика потока.
- `performance.json`: время обработки и записи по категориям, объём текстовых событий и точная причина backpressure, если он возникнет.
- `result.json`: завершённый технический результат, сделки/комиссии/net обоих портфелей и разница. `profitabilityProven=false`, `longRunReady=false`.
- `failure.json`: причина невалидного/прерванного прогона. При такой ошибке успешный финансовый отчёт не создаётся.

При разрыве/переподключении потока, пропуске стакана, ошибке REST или стратегии, превышении лимита входов, а также Ctrl+C прогон аннулируется. Это намеренно строгий режим короткой проверки. Плохие периоды не удаляются и не заменяются восстановленными данными.

## Устройство и ограничения

REST clock/scanner/context работают независимо от обработки сообщений; применение всех результатов сериализовано. Поток покрывает объединение активных символов обоих портфелей, включая символы, оставшиеся только у одного. Старшие свечи обновляются через REST; 1m догружается, когда хотя бы одному портфелю нужна коррекция. Вызовы проверки здоровья тоже записываются: они меняют диагностическое состояние часов.

Общий arbiter вызывается с интервалом из профиля. Оценка стратегий внутри market handler сохраняет исходный polling fallback каждого портфеля; event-driven фоновые задачи отключены. Это исследовательский режим, не доказанная эквивалентность всем режимам обычного сервера.

Запись синхронная, без незаметного отбрасывания данных; её влияние на задержки нужно проверить этим smoke. Лимит по умолчанию — 5 млн наблюдений. Полный поток стакана может занимать значительный объём диска. Скрипт ограничивает длительность профиля одним часом, не предназначен для незаметного продления до 72 часов.

Просадка в отчёте предварительная: выборка `balance + cached unrealized PnL` брокера на контрольных точках. Это не точная переоценка по каждой котировке и не окончательная метрика принятия E01. Уникальные кандидаты/различающиеся допуски и суточные срезы ещё требуют отчёта перед 72-часовым этапом.

`compare-e01.py` умеет проверять/читать sealed `e01-feed-v2`; повреждение цепочки, отсутствие footer, лишний хвост и отличающаяся версия исходников/окружения отклоняются. Его standalone режим пока сохраняет выходные события в памяти, поэтому полноценный повтор большого live-файла нужно запускать после оценки размера. Старые v1 synthetic fixtures поддерживаются, но не имеют защиты завершающей записью.

После завершения сообщите путь каталога. Проверяем сначала целостность, часы/свежесть, задержки и наличие ошибок, затем совпадение повторного исполнения. Нулевое количество сделок само по себе не означает поломку и не даёт оценки прибыльности.

Актуальный результат: [smoke-03 завершил 30-минутное окно](e01-smoke-03-results.md), без backpressure. Найден и исправлен хвост записи после footer; исходник сохранён, отдельно проверена завершённая часть. Следующий шаг — разбор допусков на этих данных; новый запуск пока не требуется. Для будущего smoke используйте новый каталог `data\e01-smoke-04`. Старые указания выше о неподтверждённом завершении описывают состояние до smoke-03.

Потоковый аудит новой записи на соответствующей версии кода (без исполнения стратегий):

```powershell
.\.venv\Scripts\python.exe scripts/audit-e01-capture.py data\e01-smoke-04 --output data\e01-smoke-04\analysis.json
```

Аудит не перезаписывает существующий отчёт и сохраняет строгие проверки source/runtime и завершающей записи.
